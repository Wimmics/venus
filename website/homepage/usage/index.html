Using Venus in a Web Page

VENUS is distributed as an npm package and can be directly embedded into web pages, as shown hereafter.

Get Venus and Dependencies

CDN

For quick experiments, you can import Venus Web Components directly from a CDN inside a module script. 

<script type="module">
	import "https://cdn.jsdelivr.net/npm/@wimmics/venus@latest/dist/index.js";
</script>

NPM

For production or app builds (Vite, Webpack, etc.), install from npm and import from your app entry file. 

npm install @wimmics/venus
import "@wimmics/venus";

Configuration Approaches

VENUS components support two complementary configuration approaches: Property-Based (via JavaScript) and Attribute-Based (via HTML). Choose based on your use case, or combine both for flexibility.

Approach 1: Property-Based API (Recommended for Dynamic Applications)

Configure components programmatically via JavaScript properties. This approach is most flexible and recommended for interactive applications:

<!doctype html>
<html>
<head>
	<meta charset="utf-8" />
	<meta name="viewport" content="width=device-width,initial-scale=1" />
	<title>Venus Property-Based API</title>
</head>
<body>
	<venus-graph id="vis" width="100%" height="520"></venus-graph>

	<script type="module">
		import \"@wimmics/venus\";

		const graph = document.querySelector("#vis");
		
		// Set data endpoints
		graph.sparqlEndpoint = "https://dbpedia.org/sparql";
		graph.sparqlQuery = `
			SELECT ?source ?target 
			WHERE {
				?source dbo:starring ?target
			} LIMIT 30
		`;
		
		// Configure visual encoding as a JavaScript object
		graph.encoding = {
			nodes: { field: "source" },
			links: { type: "directional" },
			interactions: { tooltip: true }
		};

		// Launch the visualization
		graph.launch();
	</script>
</body>
</html>

Advantages:

  • Clean, intuitive API
  • Full control via JavaScript
  • Complex objects (encoding) are easier to define
  • Perfect for reactive/dynamic configurations
  • Better IDE support and type checking

Approach 2: Attribute-Based API (Recommended for Static HTML)

Configure components directly in HTML using attributes. This approach is ideal for static pages and server-side rendering:

<!doctype html>
<html>
<head>
	<meta charset="utf-8" />
	<meta name="viewport" content="width=device-width,initial-scale=1" />
	<title>Venus Attribute-Based API</title>
</head>
<body>
	<script type="module">
		import \"@wimmics/venus\";
	</script>

	<!-- Configure entirely in HTML attributes -->
	<venus-graph 
		id="vis"
		width="100%" 
		height="520"
		sparqlEndpoint="https://dbpedia.org/sparql"
		sparqlQuery="SELECT ?source ?target WHERE { ?source dbo:starring ?target } LIMIT 30"
		encoding='{"nodes":{"field":"source"},"links":{"type":"directional"},"interactions":{"tooltip":true}}'>
	</venus-graph>
</body>
</html>

Advantages:

  • Declarative HTML configuration
  • No JavaScript needed for basic usage
  • Suitable for static pages and server-side rendering
  • Follows web component conventions
  • Configuration visible in HTML source

Important Considerations for Attribute-Based API:

  • JSON Escaping: Complex objects must be valid JSON strings. Use single quotes for the attribute value and double quotes for JSON keys, or escape properly.
  • Character Limits: While HTML attributes have no hard limit, very long JSON strings can be unwieldy. Consider using properties for complex encodings.
  • String Values Only: Attribute values are always strings. JSON objects and arrays must be passed as JSON strings and will be parsed internally.
  • Error Handling: Invalid JSON in attributes will be logged to console. Check browser dev tools if visualization doesn't render.

Approach 3: Hybrid API (Best of Both Worlds)

Combine both approaches for maximum flexibility. Configure static data via attributes, then update dynamically via properties:

<!doctype html>
<html>
<head>
	<meta charset="utf-8" />
	<meta name="viewport" content="width=device-width,initial-scale=1" />
	<title>Venus Hybrid API</title>
</head>
<body>
	<!-- Configure basic settings in HTML -->
	<venus-graph 
		id="vis"
		width="100%" 
		height="520"
		sparqlEndpoint="https://dbpedia.org/sparql">
	</venus-graph>

	<label>
		Search: <input type="text" id="search" placeholder="Enter actor name" />
	</label>

	<script type="module">
		import \"@wimmics/venus\";

		const graph = document.querySelector("#vis");
		const searchInput = document.querySelector("#search");

		// Initial setup via properties
		graph.encoding = {
			nodes: { field: "source" },
			links: { type: "directional" }
		};

		// Handle user input
		searchInput.addEventListener("keyup", (e) => {
			const query = `
				SELECT ?source ?target 
				WHERE {
					?source dbo:starring ?target ;
							foaf:name "${e.target.value}"
				} LIMIT 30
			`;
			
			// Update via property
			graph.sparqlQuery = query;
			graph.launch();
		});
	</script>
</body>
</html>

Advantages:

  • Declarative defaults in HTML
  • Dynamic updates via JavaScript
  • Cleanest code for interactive applications
  • Separates configuration from behavior

API Recommendations

Use Case Recommended Approach Example
Static web page Attribute-Based Render component in server template with all settings in HTML
Interactive dashboard Property-Based Update visualization on user interaction or data changes
React/Vue/Angular app Property-Based Set properties in component lifecycle (onMounted, useEffect)
Server-side rendering Attribute-Based Generate HTML with attributes from server; enhance with JavaScript
Simple query tool Hybrid Endpoint in attributes, query input via JavaScript
