Creating Visualizations with VENUS

Before exploring the editor, it is helpful to become familiar with a few basic concepts used throughout the study.

The encoding

In VENUS, the encoding describes how the data returned by the SPARQL query should be represented in the visualization.

An encoding is organized into different types of properties. Depending on the visualization, it can define:

  • Data fields are the variables returned by the SPARQL query (or contained in the SPARQL JSON results). They are used to define the graphical elements of the visualization and how they represent the data.
  • Layout properties that determine how data are positioned or arranged.
  • Marks that define the graphical elements used to represent the data, such as lines, nodes, or links.
  • Visual variables that control how a mark looks, such as color, size, stroke, or opacity.
  • Annotations that provide additional information or behavior, such as labels, tooltips.
  • Interactions that control what user interactions can be performed on the visualization, such as zoom or drag.
Important: Visual variables are defined inside the mark they modify. Layout properties, on the other hand, are defined separately at the visualization level.

Example: Line chart

A line chart uses x and y to define the horizontal and vertical positions (the layout properties). The lines mark then defines how the lines themselves are represented. 

{
    "x": {
        "field": "year"
    },
    "y": {
        "field": "temperature"
    },
    "lines": {
        "groups": {
            "field": "city"
        },
        "color": {
            "field": "city"
        },
        "size": {
            "value": 2
        }
    }
}

Here:

  • x.field uses year to determine the horizontal position.
  • y.field uses temperature to determine the vertical position.
  • lines.groups separates the data into different lines according to city.
  • lines.color uses city to determine the color of each line.
  • lines.size sets the line thickness to a constant value.

Notice that color and size are inside lines: they modify the appearance of the lines.

Keep in mind: The structure of an encoding depends on the visualization type. Cartesian visualizations such as line charts use specific layout properties such as x and y, while network visualizations define layout through marks such as nodes and links.

A useful way to read an encoding is: layout determines where things are → marks determine what is drawn → visual variables determine how marks look.

You do not need to memorize the encoding syntax. During the experiment, the Encoding Builder can help you add the available properties.
