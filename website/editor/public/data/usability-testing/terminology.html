Creating Visualizations with VENUS

Before exploring the editor, it is helpful to become familiar with a few basic concepts used throughout the study.

The encoding

In VENUS, the encoding describes how the data returned by the SPARQL query should be represented in the visualization.

An encoding is organized into different types of properties. Depending on the visualization, it can define:

  • Data fields are the variables returned by the SPARQL query (i.e. contained in the SPARQL JSON results).
    They answer the question: What data should be represented?
  • Marks are the graphical elements used to represent the data, such as lines, nodes, links, bars, or poitns.
    They answer the question: What should be drawn?
  • Layout properties control the position and arrangement of marks.
    They answer questions such as: Where should this mark be placed? or How should the marks be arranged?
    Example: in a bar chart, x and y determine the horizontal and vertical position of the bars.
  • Visual variables control the appearance of marks. Their appearance can be fixed or can change according to the data.
    They answer questions such as: What color, size, shape, or transparency should this mark have?
    Example: color can use a data field to give marks different colors depending on their category.
  • Annotations add information or explanations to the visualization.
    They answer questions such as: What additional information should be shown?
    Examples: labels that display the name or value directly next to a mark, and tooltips that display additional information when the user hover over a mark with the mouse cursor.
  • Interactions control how users can interact with the visualization.
    They answer questions such as: What can the user do with the visualization?
    Examples: users can zoom in or out to see more or less detail, or drag elements to move them.
Important: Layout properties are defined at the visualization level and determine where and how marks are arranged. Visual variables are defined for a specific mark and determine how that mark looks.

In the encoding, this means that you specify the mark you want to modify before defining its visual variables.
Example: lines.color controls the color of the lines mark, while nodes.size controls the size of the nodes mark.

Example: Line chart

A line chart uses x and y to define the horizontal and vertical positions (the layout properties). The lines mark then defines how the lines themselves are represented. 

{
    "x": {
        "field": "year"
    },
    "y": {
        "field": "temperature"
    },
    "lines": {
        "groups": {
            "field": "city"
        },
        "color": {
            "field": "city"
        },
        "size": {
            "value": 2
        }
    }
}

Here:

  • x.field uses year to determine the horizontal position.
  • y.field uses temperature to determine the vertical position.
  • lines.groups separates the data into different lines according to city.
  • lines.color uses city to determine the color of each line.
  • lines.size sets the line thickness to a constant value.

Notice that color and size are inside lines: they modify the appearance of the lines.

Keep in mind: The structure of an encoding depends on the visualization type. Cartesian visualizations such as line charts use specific layout properties such as x and y, while network visualizations define layout through marks such as nodes and links.

A useful way to read an encoding is: layout determines where things are → marks determine what is drawn → visual variables determine how marks look.

You do not need to memorize the encoding syntax. During the experiment, the Encoding Builder can help you add the available properties.
